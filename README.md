# OTT Switch

마음에 든 작품을 내 OTT로 이어 보고, 작품 중심으로 모아 두는 Chrome Manifest V3 확장 프로그램입니다. **한국 서비스 우선 · 로컬 저장 · 비공개 알파 0.1.4**

## 개발 계획

1. **기반** — 비공개 GitHub 저장소, TypeScript/React, MV3 빌드, 데이터 계약.
2. **로컬 보관함** — IndexedDB, 카테고리, 작품 편집, JSON 그룹 공유/백업, 최신 수정 우선 병합.
3. **OTT 연결** — 라프텔·애니플러스·Crunchyroll·Netflix·Prime Video·Apple TV·웨이브·티빙·쿠팡플레이·왓챠 작품 주소 인식, 검색과 보수적인 동일 작품 판정, 재생 중 숨기는 오버레이.
4. **검증 및 비공개 배포** — 단위/브라우저 테스트, 설치 가능한 ZIP, CI, 제한 사항 기록.

단위별 커밋을 만들고 각 단계가 끝날 때 `main`에 푸시합니다. 안정화 전에는 비공개를 유지합니다.

## 설계 원칙

- 작품 상세 화면과 상세 모달에서 왼쪽 오버레이를 표시합니다. 검색 목록과 실제 재생 중에는 숨기고, 상세 화면의 자동 미리보기 영상 중에는 유지합니다.
- 확인된 작품 URL로만 스위치합니다. 접속 제한, 로그인 요구, 모호한 동명 작품은 별도 상태입니다.
- 북마크의 사용자 지정 이미지/설명을 원본 페이지보다 우선합니다. 이미지는 URL만 저장하고 브라우저 캐시를 사용합니다.
- 서버 없이 로컬 데이터를 저장하며, Google Drive 계정 연결은 초기 버전에 포함하지 않습니다. 삭제 기록을 포함한 병합 구조로 이후 동기화에 대비합니다.
- 외부 데이터를 HTML로 주입하지 않고 URL과 가져오기 데이터를 검증합니다.
- 기본 확장은 WebLLM 없이 동작합니다. [선택형 WebLLM 평가 도구](eval/webllm/README.md)는 별도 설치하며, 모델을 명시적으로 불러오기 전에는 다운로드하지 않습니다. 평가 결과를 자동 이동에 연결하지 않습니다.
- [초경량 의사결정 모델 평가](eval/tiny-decision/README.md)는 실제 DOM의 여러 후보를 대상으로 LLM-as-Jev·Needle 3·Slayer와 일반 DOM 규칙을 비교합니다. 평가 도구와 모델은 기본 확장에 포함되지 않습니다.
- [확대 DOM 학습·브라우저 경량화 실험](eval/dom-scale/README.md)은 실제 OTT 120개 화면을 수집하고, 학습에서 제외한 서비스·작품으로 검증합니다. 원본 KoELECTRA부터 학습한 12층·4층 모델과 워커 실행의 비용을 비교하며, 기본 확장에는 자동 적용하지 않습니다.

## 개발

Node.js 22 이상에서 실행합니다.

```sh
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
npm run package
```

빌드 결과는 `dist/`, 설치용 ZIP은 `release/ott-switch-0.1.4.zip`에 생성됩니다. `npm run dev`는 빌드 후 `http://127.0.0.1:4173/library.html`에 보관함 미리보기를 엽니다. localhost DB는 확장 DB와 별개이며 미리보기에서는 자동 OTT 조회를 하지 않습니다.

## 설치

1. [v0.1.4 비공개 Release](https://github.com/pnpcrow/animation-ott-switch/releases/tag/v0.1.4)에서 ZIP을 받아 압축을 풉니다. 또는 위 명령으로 `dist`를 빌드합니다.
2. Chrome 주소창에서 `chrome://extensions`를 열고 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**에서 `manifest.json`이 들어 있는 폴더를 선택합니다.
4. 지원 OTT 작품 페이지를 새로고침하고 왼쪽 `OTT` 탭에서 카테고리를 선택해 저장합니다.
5. 툴바의 OTT Switch 아이콘으로 보관함을 열고 설정에서 실제 구독 중인 서비스를 선택합니다.

업데이트는 같은 폴더의 파일을 교체한 뒤 확장 **새로고침**을 사용하세요. 확장을 제거하면 로컬 데이터도 삭제되므로 먼저 JSON으로 백업하세요. 다른 설치 폴더·Chrome 프로필 간 이동도 JSON 백업을 이용합니다.

## 현재 기능

카테고리 / 작품 목록 / 대표 이미지와 소개를 분리한 3단 보관함을 제공합니다. 검색·정렬·즐겨찾기·구독 OTT 필터, 제목·이미지·설명·별칭·메모 편집과 직접 작품 추가를 지원합니다. 전체 JSON 백업과 선택 카테고리 그룹 공유가 가능하며 그룹 공유에는 개인 메모·즐겨찾기·구독 설정을 제외합니다.

공식 검색 결과의 제목과 작품 ID를 확인한 후 작품 주소로 이동합니다. HTML·브라우저 검색 후보는 대상 상세 페이지를 다시 검증하고, 라프텔 공개 카탈로그 API는 제목·작품 ID·제공 상태를 근거로 연결합니다. `Watch` 같은 시청 안내 문구는 제목 근거를 비교해 제거하며 실제 제목에 포함된 단어는 보존합니다. 동명·자막·더빙 후보가 여러 개면 사용자가 선택한 상세 페이지를 다시 검증합니다.

0.1.2에서는 자동 검색·직접 검색·보관함 검색이 같은 제목 정제 과정을 사용합니다. 구버전 북마크에 남은 한국어 제목 앞의 `Watch`도 원본 요청 실패 시 정리하며 `Watch Dogs` 같은 실제 제목은 보존합니다. JSON-LD 제목은 화면의 작품 제목과 대조하고, Crunchyroll 홈페이지의 홍보 문구를 원본 작품명이나 별칭으로 받아들이지 않습니다. 원본을 다시 읽었을 때 다른 제목이 나오더라도 기존 작품 검색어를 임의로 교체하지 않습니다.

공개 검색으로 확인하지 못한 서비스는 브라우저의 임시 탭에서 렌더링된 결과를 확인합니다. 자동 조회에서는 구독한 서비스만 이 경로를 사용하며, 각 서비스의 **찾아서 이동**을 누르면 개별 확인을 실행합니다. 임시 탭은 동시에 최대 2개이며 기존 사이트 로그인 상태를 사용합니다. 사용자가 활성화한 탭은 자동으로 이동하거나 닫지 않습니다.

0.1.3에서는 웨이브의 주소 없는 검색 카드를 지원합니다. 제목이 일치하는 프로그램·영화 카드가 하나일 때 임시 탭에서 사이트의 정상 클릭 동작을 실행하고, 이동한 공식 작품 주소와 상세 제목을 다시 확인합니다. 에피소드·에디터 추천 카드는 제외하며 같은 제목의 카드가 여러 개면 자동으로 고르지 않습니다. 작품 화면의 로고 제목·대표 이미지·전체 소개를 읽고 시즌 진입 주소를 유지합니다.

Prime Video의 공식 `phrase` 검색어는 그대로 전달합니다. 페이지 전체 이동 후 검색 결과는 표시되지만 상단 입력창이 비어 있는 경우, 공식 GET 검색 폼의 빈 필드에 URL 검색어를 한 번 반영합니다. 폼을 제출하거나 포커스를 옮기지 않으며 사용자가 수정·삭제한 값은 다시 채우지 않습니다. 한국어 `프라임 비디오:`를 포함한 지원 서비스의 제목 장식도 공통 정제합니다.

설정과 사이드바에서 검색 캐시를 초기화할 수 있습니다. 임시 검색 결과와 원본 제목 재조회 캐시, 북마크의 자동 검색 연결(`source: search`)을 비우고 다시 확인하게 합니다. 직접 연결·현재 페이지에서 저장한 링크와 북마크 제목·카테고리·메모 등은 보존합니다. 초기화 전에 시작된 결과는 나중에 자동 이동에 사용하지 않으며 사이트의 쿠키·로그인 상태는 지우지 않습니다.

라프텔 검색·홈의 작품 모달과 Netflix의 상세 모달·단독 작품 페이지를 인식합니다. Prime Video의 자동 미리보기 전환 중에는 사이드바를 유지합니다. **10개 서비스의 모든 계정과 작품에서 자동 검색을 보장하는 버전은 아닙니다.** 로그인·접근 제한·제목 불일치는 `확인 필요`로 남으며 공식 검색도 제공됩니다. 작품 페이지 확인은 구독 포함·무료 재생·한국 판권을 보증하지 않습니다. 상세 범위는 [서비스 지원표](docs/provider-support.md)에 기록했습니다.

Google Drive 연결은 **아직 구현하지 않았습니다**. 수정 시각·기기 ID·삭제 기록과 병합 구조를 준비했으며 [동기화 설계](docs/sync-design.md)에 후속 구현 원칙을 정리했습니다. 공개 저장소 전환과 Chrome 웹 스토어 등록은 안정화 후 별도 진행합니다.

## 검증 및 구조

0.1.4에서는 제공된 8개 작품의 [교차 검증 결과](docs/cross-check-2026-11-13.md)를 기록했습니다. 애니플러스의 URL 없는 카드·상세 레이어, 티빙의 `포스터`·`1화` 제목 장식, 자막/더빙 표기 위치를 보완하고 잘못된 Apple 검색 부재 판정을 수정했습니다. 단위 테스트 339개와 브라우저 회귀 테스트 28개, 선택형 평가 도구의 계약 검사 7개가 통과했습니다. 실제 카탈로그 조사와 확장 이동, 모델 품질 평가는 구분해 기록합니다.

단위 테스트는 실제 응답에서 추린 fixture, URL 경계, 검색/접근 실패, 버전 중복, 원자적 저장, 백업 검증, 병합·삭제, 메시지 경계를 검사합니다. 브라우저 테스트는 Chromium에 실제 MV3 확장을 로드해 영속 저장·오버레이·재생 감지·SPA 이동·보관함을 확인합니다. 사이트 DOM은 고정 fixture이며 실제 로그인 계정 검증을 대신하지 않습니다. GitHub Actions에도 검사·ZIP artifact 생성 워크플로를 구성했습니다.

0.1.3 타입 검사·빌드, 단위 테스트 **305개**, 브라우저 회귀 테스트 **23개**가 통과했습니다. 실제 공개 웨이브 검색을 확장에서 실행해 `어느 마녀가 죽을 때까지` 카드를 열고, `programid=CF02_CF0000000119&landing=season` 작품 주소와 상세 제목을 검증한 뒤 이동까지 확인했습니다. 로그인 후 구독 권한·본편 재생까지 검증한 것은 아닙니다. Prime Video의 검색어 전달·빈 입력창 표시와 사용자 입력 보존, 웨이브의 상세 불일치·중복 후보는 별도의 회귀 사례로 검사합니다.

2026-11-13 기준 0.1.2 단위 테스트 **229개**, 브라우저 회귀 테스트 **17개**가 통과했습니다. 실제 검색 구현에 `Watch`가 붙은 한국어 제목과 Crunchyroll 홍보 문구 별칭을 입력해 라프텔 공개 API를 조회했고, `어느 마녀가 죽을 때까지`의 작품 주소 `https://laftel.net/item/42783`으로 연결 가능한 결과를 확인했습니다. 검색 결과는 1개이며 만료되지 않은 제공 상태였습니다. Crunchyroll에서 다른 OTT로 이동하는 브라우저 경로는 재현 DOM과 응답을 사용해 검증하며 실제 로그인 계정 검증을 대신하지 않습니다.

0.1.1에서 실제 공개 라프텔 검색의 모달 열기·닫기와 미리보기 중 사이드바 유지를 확인했습니다. Netflix·Prime Video 검증도 재현 DOM을 이용한 확장 브라우저 테스트이며 모든 로그인 계정 상태를 실측한 것은 아닙니다. GitHub Actions는 계정 예산 제한(`The job was not started because an Actions budget is preventing further use.`)으로 실행되지 않았습니다. 예산 제한 해결 후 Actions에서 수동 실행할 수 있습니다.

`src/providers`는 사이트 어댑터, `src/background`는 네트워크/저장 메시지 처리, `src/content`는 Shadow DOM 오버레이, `src/core`는 DB/백업, `src/library`는 React 보관함입니다.
