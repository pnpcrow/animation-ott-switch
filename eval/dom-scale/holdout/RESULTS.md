# 독립 미학습 DOM 검증 결과

이번 모델은 확장기능의 자동 추출·이동 판단에 기본 적용할 수준에 도달하지 못했다. **양성 작품 페이지 24개에서 제목·대표 이미지·소개를 동시에 맞힌 페이지는 네 조건의 native 실행과 최종 선택 조건의 실제 브라우저 실행 모두 0개**다. native 전체 정확도는 40.0~45.0%, 실제 브라우저는 41.7%로, 아무 모델 없이 항상 none을 고르는 40.0% 기준선과 가깝다. 모델 크기와 계산 시간을 줄였다는 결과를 유용한 추출 정확도를 확보했다는 뜻으로 해석하면 안 된다.

이는 이번의 제한된 DOM 후보, KoELECTRA 초기 모델, 수집·표현 방식, 소규모 자료와 3 epoch 학습 설정에 대한 결과다. 모든 초소형 모델이나 DOM 학습 자체가 불가능하다는 결론은 아니다. 평가 이후 모델·정답·후보·템플릿을 재튜닝하지 않았다.

## 평가 설계와 분모

학습/설계 담당자에게 작품·URL·후보·정답을 가린 상태로 자료를 수집하고 주석을 동결했다. 모델 설정·가중치·전처리·런타임과 개발 검증 기반의 최종 브라우저 선택까지 동결한 뒤 평가를 실행했다. 실행 직전 재현성 감사의 206개 해시 검사가 모두 통과했다.

- 수집 52시도 중 40페이지, 제목·이미지·소개 120필드를 채점했다. 12시도는 모델 결과를 보기 전에 의미상 중복, 미작동 후 동일 화면, 아직 로딩 중인 화면으로 제외했으며 수집 분모와 원본 기록에는 남겼다.
- Netflix·Apple TV 전체를 학습에서 제외한 **미학습 서비스 69필드**, Laftel·TVING의 예약 미학습 작품 **51필드**를 분리했다. 실제 작품 family는 12개다.
- 양성 24페이지/72필드, 검색·로그인·차단·전체 재생 등 none 정답 16페이지/48필드다. none만 후보로 남은 자명한 2필드는 추론을 생략한다. 비교 선택 문제는 118개이며 전체 120분모에 모두 포함한다.
- 원본 최대 18후보 중 앞 12개와 none을 고정 제공했다. 양성 정답이 후보에서 빠진 3필드는 모든 조건에서 실패로 남겼다. 정답을 none으로 바꾸거나 후보를 삽입하지 않았다.
- 공개 DOM 35페이지와 개인정보를 제외한 인증 DOM 5페이지는 수집 변형이 달라 별도 집계했다. 인증 상태를 공개 캡처와 동일한 수집 방식으로 간주하지 않는다.

최초 세 조건은 12층 natural384, 12층 compact160, 4층 compact160이다. 개발 검증에서 compact 표현이 none 위주로 붕괴한 것을 확인한 부모 작업은 **held-out 실행 전에** 4층 natural384를 보충 조건으로 추가했다. 같은 seed·3 epoch·학습 분할을 유지했고 원래 세 조건을 삭제하지 않았다. 보충 조건을 최초 계획에 포함됐던 것처럼 보고하지 않는다. 변경 이력은 [EVALUATION.md](EVALUATION.md), [보충 계획](supplemental-evaluation-plan.json), `supplemental-history/`에 남겼다.

## Native q8 정확도

아래는 동일 후보를 한 필드 단위 full batch로 처리한 결과다. `양성 추출`은 작품 정보가 있는 72필드에서 올바른 후보를 선택한 수다. `none 오탐`은 정답이 none인 48필드에서 실제 요소를 잘못 선택한 수다.

| 조건 | 전체 정답 | 양성 추출 | none 정답 | none 오탐 |
|---|---:|---:|---:|---:|
| 항상 none | 48/120 (40.0%) | 0/72 (0.0%) | 48/48 | 0/48 |
| 12층 natural384 | 53/120 (44.2%) | 12/72 (16.7%) | 41/48 | 7/48 |
| 12층 compact160 | 50/120 (41.7%) | 2/72 (2.8%) | 48/48 | 0/48 |
| 4층 compact160 | 48/120 (40.0%) | 0/72 (0.0%) | 48/48 | 0/48 |
| 보충 4층 natural384 | 51/120 (42.5%) | 9/72 (12.5%) | 42/48 | 6/48 |

4층 compact160은 120문제 모두 none을 골랐다. 12층 compact160도 양성 추출은 두 필드뿐이다. 이 두 조건의 none 오탐 0을 추출기가 안정적이라는 근거로 사용할 수 없다.

12층 natural384의 양성 제목/이미지/소개 정답은 각각 **0/24, 7/24, 5/24**다. 보충 4층 natural384는 **4/24, 3/24, 2/24**다. 전체 세 필드 일치 페이지 13~16/40은 모두 none 페이지에서 나왔으며, 양성 페이지의 완전 추출은 모든 조건에서 0/24다.

후보 누락 3개를 제외한 조건부 정확도도 12층 natural384 53/117(45.3%), 12층 compact160 50/117(42.7%), 4층 compact160 48/117(41.0%), 보충 4층 natural384 51/117(43.6%)에 그친다. **실패 대부분을 세 후보 누락으로 설명할 수 없다.**

## 배치 크기에 따른 결과 차이

동적 q8 실행에서는 후보를 한꺼번에 처리하는 full batch와 2개씩 나누는 micro2가 완전히 같은 출력을 내지 않았다. 실행 성공, 점수 근사치, 최종 선택의 일치는 서로 다른 검증 항목이다.

| 조건 | full 정답 | micro2 정답 | 동일 선택 | 최대 절대 logit 차이 |
|---|---:|---:|---:|---:|
| 12층 natural384 | 53/120 | 54/120 | 114/120 | 0.9773 |
| 12층 compact160 | 50/120 | 50/120 | 120/120 | 0.6316 |
| 4층 compact160 | 48/120 | 48/120 | 120/120 | 0.7318 |
| 보충 4층 natural384 | 51/120 | 50/120 | 96/120 | 0.6356 |

각 실행의 오류는 0이고 후보 누락 세 문제는 양쪽 모두 실패다. 보충 모델에서 micro2는 full에 비해 정답 3개를 얻고 4개를 잃었다. parent의 최종 브라우저 full-batch 선택은 이 held-out 결과를 보기 전 개발 q8 결과(full 42/57, micro2 40/57, 선택 일치 50/57)로 결정했다. held-out에서 더 나아 보이는 배치를 다시 골라 보고하지 않는다.

Native CPU의 필드당 추론 중앙값/p95는 full 기준 12층 natural384 115.6/158.7ms, 12층 compact160 60.6/90.1ms, 4층 compact160 24.0/32.6ms, 보충 4층 natural384 42.2/60.1ms였다. 이는 같은 장비의 native ORT 측정이며 **브라우저 처리 시간으로 대체하지 않는다**. 모델 q8 파일은 12층 14,700,237바이트, 4층 7,969,650바이트로 약 45.8% 작아졌다. 파일 크기는 브라우저 실제 메모리 사용량이 아니다.

## 대표 오류와 정보 손실

1. **작품 이미지 대신 공급자 아이콘 선택:** `h015-image`, Apple TV의 모브사이코100에서 보충 모델은 작품 hero `i1`/`i2` 대신 `i4` WATCHA 아이콘을 골랐다. 원본 DOM은 작품 hero 1200×675, 공급자 아이콘의 렌더 크기 23×23 및 부모 `aria-label=WATCHA`를 구분한다. 그러나 실제 natural 입력 문장에는 렌더 크기와 부모 label이 빠지고 아이콘의 원본 크기 1440×1440만 남는다. DOM에 증거가 있었다는 사실과 모델에 그 증거가 전달됐다는 사실은 다르다.
2. **현재 작품명 대신 에피소드명 선택:** `h051-title`, Netflix 인증 검색 모달에서 보충 모델은 `t11` 코미 양은 커뮤증입니다 대신 `t12` 말하고 싶습니다를 골랐다. 두 후보 모두 같은 현재 모달 안에 있으나 정답은 848×477 작품 이미지의 alt, 오답은 341×192 에피소드 카드의 alt다. 실제 입력에도 문서의 작품명, 부모 dialog/button, 크기 차이가 있었지만 구분하지 못했다. 이 사례는 정답이 고정 12후보 안에 있어 후보 누락 실패가 아니다.
3. **차단 모달 아래의 정보 선택:** `h042-title`, TVING 구독 안내 모달에서 12층 natural384는 정답 none 대신 배경 문서의 `t1` 외톨이 THE ROCK! 1화 | TVING을 골랐다. 모달은 실제 구독 안내였고 정답 정책상 차단 상태이지만, natural 문장에는 대화상자 수 1과 배경 작품 정보만 남고 구독 모달의 본문이 전달되지 않는다. 작품/에피소드 구분과 활성 모달 범위 표현 모두 한계가 드러난다.

구독 차단 모달을 none으로 정한 것은 이번의 보수적인 평가 정책이다. 실제 제품은 미구독 OTT에서도 작품 상세가 확인되면 다른 OTT로 이동할 수 있어야 하므로 배경 작품 정보를 유지할 필요가 있다. 따라서 이 정책에서의 오탐을 그대로 제품 요구 위반으로 등치하지 않으며, 차기 라벨 정책 검토 대상으로 남긴다. 현재 정답·점수는 바꾸지 않았고 양성 24페이지의 완전 추출 0이라는 별도 결과는 그대로다.

인증 Netflix에서는 홈페이지/검색 결과의 이미지가 먼저 쌓여 현재 작품 대표 이미지가 원본 18후보에도 없는 두 사례, 깨끗한 작품명이 원본에는 있으나 12후보 밖인 한 사례가 있었다. 별도 실제 DOM 증거를 보존했지만 모델 후보에 보충하지 않았다. 이 실패는 모델의 선택 성능과 별개인 후보 수집 재현율 문제다.

## 모달·재생 검증 범위

작품 모달 6페이지/18필드의 full 정답은 12층 natural384 1/18, compact 두 조건 0/18, 보충 4층 natural384 4/18이었다. Apple의 소개 확장 모달 2페이지/6필드는 네 조건 모두 0/6이다. 제목만 있는 주소나 `modal` 파라미터를 근거로 실제 모달을 확보했다고 계산하지 않았다.

실제 전체 재생은 인증 Netflix 두 작품에서만 확보했다. `paused=false`, `readyState=4`, 양의 재생 시간과 큰 영상 영역을 확인하고 곧바로 탭을 닫았다. 여섯 none 필드는 네 조건에서 모두 맞혔지만, 항상 none도 동일하게 맞힐 수 있다. 다른 서비스의 실제 재생이나 모든 로그인/미리보기 전환에 대한 일반화 근거가 아니다. 상세 모달 안의 미리보기 영상은 전체 재생으로 라벨링하지 않았다.

공개 DOM 정확도는 full 기준 12층 natural384 44/105, compact12층 41/105, compact4층 39/105, 보충 natural4층 41/105다. 인증 DOM은 각각 9/15, 9/15, 9/15, 10/15이며 양성 여섯 필드 중 정답은 각각 0, 0, 0, 1이다. 인증 상태의 수가 작고 수집 변형도 달라 단순 비율만으로 우열을 해석할 수 없다.

## 실제 브라우저 결과

개발 검증으로 미리 선택한 보충 4층 natural384 / full batch / worker / WASM 1 thread / 브라우저 tokenizer 구성을 **전체 120필드에서 실제 실행**했다. Windows 10.0.26300, Ryzen 7 8840U, Chromium 158.0.8127.18 환경의 격리 브라우저다. GPU가 아니라 WASM CPU 실행이며 WebGPU 성능을 입증한 결과가 아니다.

실제 `result.cases.valid/selected`로 독립 채점한 결과는 valid 120/120, 실행 오류 0, **정답 50/120(41.7%)**다. 양성은 9/72(12.5%), none 정답은 41/48이고 none 오탐은 7/48이다. 양성 페이지 완전 추출은 0/24, 후보가 있는 문제만 조건부 채점해도 50/117(42.7%)다. 전체 정확도의 작품 cluster 95% 구간은 24.1~52.5%다.

| 실제 브라우저 집계 | 전체 정답 | 양성 정답 |
|---|---:|---:|
| 미학습 서비스 | 17/69 (24.6%) | 2/51 |
| 미학습 작품 | 33/51 (64.7%) | 7/21 |
| Netflix | 12/36 | 0/24 |
| Apple TV | 5/33 | 2/27 |
| Laftel | 18/27 | 3/12 |
| TVING | 15/24 | 4/9 |

Native full과 브라우저의 선택은 **103/120개만 일치**했고 최대 절대 logit 차이는 0.27435였다. 브라우저에서 정답 3개를 얻고 4개를 잃었다. 토크나이저 parity와 실행 성공이 선택/정답의 동일성을 보장하지 않으므로 native 정확도를 브라우저 정확도로 복사하지 않았다.

| 관측 시점 중 최대 / 시작 대비 증가 | 639.4 / 249.4MiB |
| worker 종료 1초 뒤 / 시작 대비 잔류 증가 | 456.7 / 66.8MiB |

필드 처리 시간에는 DOM 수집·템플릿 작성·모델 로드·보고용 메모리 관측이 포함되지 않는다. 모델 로드는 로컬 loopback에서 측정해 인터넷 다운로드 시간이 아니다. 메모리는 브라우저 전체 프로세스의 시점별 작업집합 합계로 공유 페이지 중복과 브라우저 부하가 포함될 수 있고, 연속 측정한 최대 물리 RAM이나 모델만의 메모리가 아니다. worker를 명시적으로 종료한 후의 감소이며 자동 메모리 회수의 증거로 일반화하지 않는다. 메인 스레드 타이머의 최대 간격은 약 26.0ms였지만 사용자 입력 지연을 직접 측정한 지표가 아니다.

동일 개발 검증 자료에서 반복한 구성 간 브라우저 시간·메모리 비교는 별도 [전체 런타임 결과](../runtime/all-summary.json)를 참고한다. 이 문서의 held-out 실행은 선택된 구성 한 개의 실제 확인이며, 이 값만으로 다른 구성 대비 메모리 감소율을 계산하지 않는다.
