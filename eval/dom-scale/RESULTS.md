# 확대 DOM 학습·브라우저 비용 평가 — 2026-11-14

수집, 파인튜닝, 미학습 서비스·작품 검증, 실제 브라우저 측정을 완료했다. **현재 모델은 기본 추출기로 적용할 수준에 도달하지 못했다.** 사전 선택한 4층 모델의 실제 브라우저 정확도는 **50/120(41.7%)**, 작품 정보가 있는 필드의 추출 성공은 **9/72(12.5%)**다. 양성 작품 페이지 24개 중 제목·이미지·소개를 모두 맞힌 페이지는 **0개**다. 항상 NONE을 반환하는 기준선은 48/120(40%)이다.

속도와 모델 크기는 줄었지만 정확도가 충분하지 않다. 평가 코드는 기본 확장 경로와 분리해 보관하며, 이 결과를 OTT 전환 기능의 정확도 개선이나 실제 제품 배포 완료로 해석하지 않는다.

## 데이터와 검증

지원 10개 서비스에서 **120개 화면 / 360개 필드 판단**을 확보했다. 상세·모달·검색·접근 제한·실제 재생 상태를 포함한다. 모든 서비스의 모든 상태를 확보했다는 뜻은 아니다.

- 개발 자료: 라프텔·애니플러스·크런치롤·프라임비디오·웨이브·티빙·쿠팡플레이·왓챠의 80화면/240필드. 중복 27개와 후보 수집 누락 3개를 제외한 210개를 작품 단위로 학습 153개/개발 검증 57개로 분리했다. 실제 작품 그룹은 13개로 여전히 작다.
- 독립 검증: Netflix·Apple TV 전체를 파인튜닝/개발에서 제외한 69필드와, 라프텔·티빙의 예약 미학습 작품 51필드. 총 40화면/120필드, 12작품 family다. 모델 담당자는 가중치·입력·선택 규칙을 고정하기 전 이 자료를 열람하지 않았다.
- 실제 본편 재생은 개발의 라프텔·크런치롤·쿠팡플레이 각 1화면과 검증의 Netflix 2화면, 총 5화면이다. 로그인·구독 안내나 자동 미리보기를 본편으로 세지 않았다.
- 검증 후보 누락 3개는 실패 분모에 유지했다. 기존에 소비한 84문제와 과거 파인튜닝 가중치는 새 학습에 넣지 않았다.

수집·익명화·중복과 누락 근거는 [수집 검토](collection-train/REVIEW.md), 전체 절차는 [프로토콜](README.md)에 있다. 구독 차단 모달을 NONE으로 보는 이번 보수적 라벨 정책은 실제 제품의 미구독 OTT 간 이동 요구와 다를 수 있어 별도 검토 대상이며, 평가 후 정답은 바꾸지 않았다.

## 모델 결과

원본 KoELECTRA의 고정 revision부터 같은 seed·학습 순서·3 epoch로 학습했다. 최초 세 조건의 입력 압축 실패를 개발 검증에서 확인한 뒤, 독립 검증 실행 전에 자연어 입력을 유지하는 4층 조건을 추가했다. 원래 조건과 동결 기록을 모두 보존했다.

| 조건 | q8 모델 파일 | 개발 FP32 | 독립 native q8 full | 해당 양성 추출 |
| --- | ---: | ---: | ---: | ---: |
| 12층, 자연어 입력 | 14.70MB | 39/57 | 53/120 (44.2%) | 12/72 |
| 12층, 짧은 입력 | 14.70MB | 33/57 | 50/120 (41.7%) | 2/72 |
| 4층, 짧은 입력 | 7.97MB | 33/57 | 48/120 (40.0%) | 0/72 |
| **후속 4층, 자연어 입력** | **7.97MB** | **41/57** | **51/120 (42.5%)** | **9/72** |

개발 기준으로 선택한 후속 모델을 실제 Chromium에서 full batch로 실행하면 **50/120**이었다. native와 최종 선택은 103/120만 같았고 정답 3개를 얻고 4개를 잃었다. 토큰은 Python과 정확히 일치했으며 실행 오류는 없었다. 런타임 실행 성공과 추출 정확도는 별개다.

실제 브라우저의 미학습 서비스 성능은 **17/69(24.6%)**, 같은 서비스의 미학습 작품 성능은 **33/51(64.7%)**다. 후자의 높은 전체 비율에도 NONE 정답이 많이 포함되어 있다. 실제 작품 정보 72필드 중 9개만 맞혔고, NONE 정답 48필드 중 7개에서 엉뚱한 요소를 선택했다. 일반화 개선이나 정확도 유지가 입증되지 않았다. 세부 서비스·필드·신뢰구간·원시 선택은 [독립 검증 보고서](holdout/RESULTS.md)에 있다.

## 브라우저 처리 시간과 메모리

같은 **개발 검증 57필드**를 구성별로 새 Chromium에서 **2회** 실행했다. 모델을 실행할 필요 없는 NONE 단일 후보 1개를 제외한 56필드의 처리 시간이다. 아래 범위는 두 실행 결과이며 통계적 신뢰구간이 아니다.

| 구성 | 브라우저 개발 정답 | 필드 처리 p50 | p95 | 전체 관측 최대 WS | 종료 1초 후 WS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 12층 자연어, main/full | 39/57 | 1,196~1,208ms | 1,871~1,950ms | 617~622MiB | 616~622MiB |
| 같은 모델, worker/micro2 | 39/57 | 1,023~1,035ms | 1,715~1,810ms | 605~606MiB | 467~471MiB |
| 12층 짧은 입력, worker/micro2 | 33/57 | 510~524ms | 936~1,019ms | 597~598MiB | 465~475MiB |
| 4층 짧은 입력, worker/micro2 | 33/57 | 175~205ms | 331~344ms | 575MiB | 472~473MiB |
| **4층 자연어, worker/full** | **42/57** | **411~424ms** | **632~685ms** | **613~617MiB** | **476~477MiB** |
| 같은 모델, worker/micro2 | 39/57 | 348~350ms | 556~561ms | 597MiB | 463~466MiB |

선택한 4층 full 구성은 12층 main/full 대비 두 실행 p50 평균이 약 **65%**, 모델 파일이 약 **46%**, 종료 후 WS 평균이 약 **23%** 감소했다. **전체 관측 최대 메모리는 거의 같았다.** 이는 모델 깊이·worker 구성이 함께 바뀐 비교이며 worker 단독의 가속 효과가 아니다. Full 선택은 독립 평가 전에 확인한 native q8 개발 결과(full 42/57, micro2 40/57)를 근거로 고정했다. 이후 실제 브라우저 개발 측정에서도 micro2는 full의 42/57보다 낮은 39/57이었다. 후속 모델 4회 측정은 기존 구성 8회 뒤에 실행되어 순서·장비 열 상태에 따른 차이가 남을 수 있다.

측정 환경은 Ryzen 7 8840U, Windows, Chromium 158.0.8127.18, ONNX Runtime Web 1.31.1, WASM 1 thread다. GPU를 요구하지 않는다. 시간은 토큰 변환·padding/정합 검사·텐서 생성·추론·결과 읽기·해제를 포함하며 DOM 수집, 입력 문장 작성, fixture I/O, 모델 로딩과 보고 I/O는 제외한다. 한 페이지 전체 표시 시간이 아닌 **필드 후보 목록 하나의 처리 시간**이다.

WS는 격리 Chromium의 프로세스별 working set 합계다. 브라우저 기본 비용과 공유 페이지 중복 계산이 포함되며, 실제 설치된 확장의 추가 물리 메모리나 연속 peak 측정이 아니다. 최대값은 종료 이후 관측도 포함한다. 초기 whole-browser WS는 약 387~393MiB였다. Worker 종료를 통한 유휴 메모리 회수 개선은 확인했지만 모델 파일 축소율을 RAM 절감률로 대체하지 않았다.

별도의 독립 검증 120필드를 처리한 선택 모델의 실제 브라우저 p50/p95는 **507/673ms**(추론 필요 118필드)였다. 모델 로딩 366ms와 tokenizer 로딩 46ms는 별도이며 인터넷 다운로드 시간은 아니다. 이 실행의 WS는 390→관측 최대 639→종료 1초 후 457MiB였다. 정확도 표와 성능 비교 표의 데이터 분모가 다름에 유의한다. 원시 측정과 해시는 [12회 측정 집계](runtime/all-summary.json), [독립 브라우저 실행](runtime/holdout-small-natural-full.json)에 보존했다.

## 확인한 문제와 반영한 개선

실제 화면에서는 작품 이미지 대신 작은 OTT 공급자 로고를 선택하거나, 작품명 대신 회차명을 골랐다. 후보에 정답이 있어도 활성 모달·에피소드·배경 페이지를 충분히 구분하지 못했다. 일부 DOM 증거는 수집됐으나 모델 입력 문장으로 만드는 과정에서 렌더 크기와 부모 aria-label 등이 빠졌다. 후보 수집 누락 3개만으로 대부분의 오답을 설명할 수 없다.

이번에는 dedicated worker, 한 필드씩 입력 전달, 즉시 텐서 해제, 세션 해제·worker 종료, 실제 브라우저 tokenizer parity 검사, 오류를 분모에서 유지하는 평가를 구현했다. 짧은 입력과 microbatch는 별도 비교 조건으로 남겼다. 다음 자료 개선에서는 렌더 크기·부모 label·활성 범위·작품/회차 관계를 보존하고 작품 다양성과 라벨 정책을 보강해야 한다. 현재 검증 답을 이용해 모델이나 템플릿을 고치지는 않았다.

## 검증과 보관

타입 검사, 기존 단위 테스트 339개, 새 Node 계약 테스트 10개, 모델 Python 계약 테스트 11개와 빌드가 통과했다. 네 모델의 동적 ONNX shape 검증, 실제 브라우저 12회 성능 실행 및 독립 120필드 실행에서도 오류가 없었다. GitHub Actions는 계정 예산 제한으로 작업이 시작되지 않았다.

모델·데이터·선택·평가 코드는 [전체 동결](global-freeze.json)에 연결하고 단계별로 커밋·푸시했다. 모델 가중치는 로컬 `.tmp/dom-scale`에 있으며 원본 revision, 학습 설정과 SHA256을 기록했다. 독립 browser job JSON 160.3MB는 바이트를 그대로 복원할 수 있는 gzip 3.67MB로 보관한다. 복원 명령은 `node eval/dom-scale/holdout/archive-browser-plans.mjs --restore`다. [압축 자료 manifest](holdout/browser-plan-archives/manifest.json)에 원본·압축 해시가 있다.

최종 [검증 기록](verification.json)은 동결 해시 206개, 실제 브라우저 실행 13회, 압축 계획 8개의 무결성과 실행 계약을 확인한다. 이 검사는 모델 정확도나 수동 정답의 완전성을 보증하지 않는다.
