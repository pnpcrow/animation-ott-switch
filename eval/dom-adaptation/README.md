# DOM 역할 학습과 입력 표현 재검토

이 단계의 목적은 사람이 설계한 특징에 계수를 학습한 6.5 KB 선형 모델을 범용 DOM 이해 모델로 확대 해석하지 않고, **언어·구조 표현을 학습하는 소형 신경망**과 모델의 학습 방식에 맞는 입력 표현을 검토하는 것입니다. 과거 결과는 특정 관측 표현과 설정의 결과이며, 템플릿 개선이나 과제 학습의 가능성을 기각하지 않습니다. 확장 프로그램 본체와 기본 실행 경로는 변경하지 않습니다.

최종 측정값은 [RESULTS.md](RESULTS.md), 조사와 공식 출처는 [RESEARCH.md](RESEARCH.md)에 있습니다. 실험은 다음 세 부분을 구분합니다.

1. **입력 표현**: 기존 NLI 모델에 JSON 대신 자연어 DOM 관측과 선언형 역할 가설을 제공합니다. 단순 역할, 후보 값 명시, 제외 역할 대비, 한국어 표현을 개발 자료에서 비교합니다. NLI에 대화형 지시를 길게 넣는 것이 지시 따르기 학습을 대신하지는 않습니다.
2. **과제 학습**: 한국어 소형 encoder에 후보 점수 head를 붙여 실제 작품 제목·이미지·줄거리와 `none`을 학습합니다. encoder를 고정한 head 학습과 encoder까지 학습하는 조건을 같은 초기화·자료·입력에서 비교합니다. 사전학습 encoder의 무작위 head를 zero-shot 추출 모델로 평가하지 않습니다.
3. **평가 분리**: 작품만 바뀐 익숙한 레이아웃, 학습에 없던 서비스, 실제 DOM 개편은 서로 다른 평가입니다. 교차 서비스 실험에서는 같은 작품의 다른 서비스 페이지도 학습에서 제거합니다.

두 학습 조건은 초기 가중치와 입력 자료를 공유하지만 head 학습률·batch·dropout·학습 횟수도 다릅니다. 따라서 두 고정 학습 설정의 탐색 실험이며, 결과 차이를 encoder 업데이트만의 단일 효과로 해석하지 않습니다.

## 현재 자료의 한계

이전 실험에서 사용한 84개 필드 문제는 **모두 소비된 개발 자료**입니다. 원본 경로의 `holdout`이라는 이름을 유지하더라도 이번 단계에서 새 독립 검증으로 부르지 않습니다. 66개로 학습하고 이전 18개를 비교하는 수치는 회고적 개발 진단입니다. 최종 설정을 고정한 뒤 새로 수집하고 별도로 주석한 자료가 있어야 신규 성능을 주장할 수 있습니다.

`corpus-audit.json`은 28페이지·10개 서비스·16개 작품 그룹을 기록합니다. 실제 작품 필드는 59개, 부재 필드는 25개이고, 부재 중 후보가 아예 없는 문제 2개는 따로 셉니다. 10개 서비스 중 7개는 이 표본에 양성 또는 부재 사례 중 한쪽만 있습니다. 따라서 현재 자료만으로 서비스별 오탐률과 추출률을 함께 검증할 수 없습니다.

`protocol.mjs`의 provider별 분할은 서비스 전체를 평가 쪽에 두고, 평가에 등장하는 작품의 다른 서비스 자료를 학습에서 제외합니다. 같은 페이지의 제목·이미지·설명을 쪼개지 않습니다. `corpus-audit.json`에 저장된 10개 분할은 **실행 계획이지 측정 결과가 아닙니다**. 각 모델 보고서가 명시적으로 실행한 분할만 결과로 읽습니다. 이 분할 또한 이미 검토한 자료의 개발 진단이며, 새로운 시험 자료가 아닙니다.

원본의 `none-search` 그룹 중 라프텔의 스파이 패밀리 검색 페이지는 명시적인 작품 식별을 갖습니다. 원본 frozen 자료를 바꾸지 않고, URL 근거를 검사하는 분할 전용 보정으로 Apple 평가 때 이 검색 자료도 학습에서 제외합니다. 전체 페이지의 모든 추천 작품 언급까지 식별한 것은 아니므로, 여기서 작품 분리는 주석된 대상 작품과 명시적 검색 대상을 기준으로 합니다.

```powershell
node eval/dom-adaptation/audit-corpus.mjs
npm run test:dom-adaptation
```

감사 코드는 잘못된/중복된 정답 ID, 입력과 정답의 불일치, 서비스·작품·페이지 누출을 거부합니다. 서비스/작품 식별자는 분할에만 쓰며 모델 입력에는 넣지 않습니다. 원본 frozen 실험의 파일과 가중치는 수정하지 않습니다.

## 적용 전에 필요한 다음 평가

- 실제 페이지마다 모달 열기 전후, 배경 추천 영역, 메타데이터와 본문 충돌, 제목 로고/작품 이미지/회차 이미지, 로그인·검색·약관·재생 화면과 필드 일부 부재를 포함합니다.
- DOM의 parent/child 관계, 후보가 속한 영역, 실제 관측한 가시성·포커스·inert 상태를 보존합니다. 마지막 DOM 다이얼로그가 실제 최상위 모달이라고 가정하지 않습니다. 알 수 없는 속성을 거짓으로 변환하지 않습니다.
- 긴 프롬프트 하나에 모든 판단을 맡기기보다 상세 화면 여부, 현재 영역, 필드 역할, 보류를 별도 학습 목표로 검증합니다. 출력은 원문 후보 ID로 제한하고 실제 텍스트/URL은 해당 DOM에서 복사합니다.
- CSS 클래스 교체, 의미 없는 wrapper 추가, 후보 순서 변경은 의미 보존 진단입니다. 합성 변형을 새 실제 사이트 표본처럼 세지 않습니다. 페이지의 작품을 바꾸거나 보이는 영역을 바꾸는 변형은 정답도 바뀌므로 불변성 검사에 넣지 않습니다.
- 원본과 양자화 모델의 선택 결과, 후보 정답 포함률, 작품 필드 추출률, 비작품 오탐률, 보류율을 함께 봅니다. 모델 점수나 softmax를 검증된 정답 확률로 부르지 않습니다.
- 후보별 encoder 평가가 만족스럽다면 작은 listwise/head 또는 구조 embedding을 추가해 후보 사이의 관계를 학습할 수 있습니다. 증류용 큰 DOM 모델은 개발 환경에서만 사용하고, 자동 주석은 사람이 확인한 정답과 구분해야 합니다.
- Chrome WASM/WebGPU의 실제 지연·추가 메모리·다운로드를 측정한 뒤 선택 기능으로 적용합니다. 작은 adapter나 적은 학습 계수는 배포할 base 모델 용량을 없애지 않습니다.

파인튜닝과 템플릿 개선은 일반화를 **가능하게 하는 실험 방향**이며, 소량 학습만으로 사이트 개편에 강해졌다는 결론은 아닙니다. 학습 자료를 늘릴 때도 서비스·작품·캡처 시점을 분리한 자료에서 실제 개선이 유지되는지 확인해야 합니다.
