# DOM 템플릿·소형 모델 파인튜닝 결과

2026-11-13. 이번 결과는 **손으로 설계한 특징의 추가 튜닝만으로 일반화를 기대하기보다, 관측 표현·학습 과제·서비스 분리 검증을 함께 개선해야 한다**는 방향을 뒷받침합니다. 한국어 소형 encoder를 실제 DOM 후보 선택으로 파인튜닝하고 14.7 MB ONNX로 내보내 Chrome에서 실행했습니다. 그러나 사이트 일반화와 실행 비용이 모두 해결된 단계는 아닙니다. 확장 프로그램 본체에는 적용하지 않았습니다.

기존 6.5 KB 모델도 가중치를 학습한 통계 모델이지만, 사용할 수 있는 의미 정보가 사람이 만든 특징에 제한됩니다. 이번 KoELECTRA는 관측 문장에서 후보 표현을 학습합니다. 다만 표준 한국어 encoder이며 전체 DOM/XPath를 사전학습한 모델은 아닙니다. [조사](RESEARCH.md)에는 DOM 특화 모델과 Needle의 실제 입력 계약도 정리했습니다.

## 템플릿만 변경한 실험

같은 NLI checkpoint에 자연어 DOM 관측, 값이 포함된 가설, 대조 역할 가설, 한국어 표현을 시험했습니다. 개발 66문제로 선택한 새 설정은 27/66이었지만 기존에 이미 본 18문제에서는 6/18이었습니다. 기존 JSON 설정의 21/66, 7/18과 비교하면 전체 개선을 보이지 않았습니다.

새 설정은 작품 필드 정답을 1/12에서 5/12로 늘렸지만 오선택도 1건에서 11건으로 늘렸습니다. 입력 표현·언어·가설·threshold가 함께 달라진 선택 설정 간 비교이므로 표현 하나의 효과로 분리할 수 없습니다. 다른 템플릿의 회고 점수를 보고 승자를 다시 고르지 않았습니다. 336개 문제 조건·2,156개 후보 추론에 오류는 없었습니다. [전체 템플릿 결과](templates/README.md).

## 실제 파인튜닝

`KoELECTRA-small-v3`에 scalar ranking head를 붙였습니다. 두 조건은 동일한 초기 encoder/head와 관측 입력으로 시작합니다. 하나는 encoder를 고정하고 head 257개 계수를 학습하며, 다른 하나는 전체 14,056,449개 계수를 학습합니다. 후보별 점수에 listwise loss를 적용하고, 여러 공식 정답을 허용하며 `none`도 선택지로 학습합니다.

| 조건 | 학습 66문제 | 회고 18문제 | 회고 작품 필드 /12 | 회고 부재 /6 | 회고 오선택 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Encoder 고정 + head 학습 | 50 | 6 | 3 | 3 | 10 |
| Encoder 전체 + head 학습 | 46 | 11 | 7 | 4 | 6 |

회고 18문제 중 1개는 실제 후보가 없는 자동 `none`입니다. 이를 제외하면 5/17과 10/17입니다. 기존 6.5 KB 구조 모델의 같은 자료 점수는 14/18이었으므로, 이번 파인튜닝이 이미 그 기준을 넘어섰다는 결과가 아닙니다. 의미 표현을 학습하는 경로를 구현하고 한계를 실측한 단계입니다.

두 학습 방법은 batch, head 학습률, dropout과 학습 횟수도 다릅니다. 따라서 6→11의 차이를 encoder 업데이트만의 인과 효과라고 주장하지 않습니다. 무작위로 초기화한 head의 출력을 zero-shot 성능으로 보고하지 않았고, 결과를 본 뒤 학습 횟수나 threshold를 다시 고르지 않았습니다. [학습 설정·재현](finetune/README.md).

## 사이트를 분리하면

넷플릭스 전체와 그 평가 대상 작품의 다른 서비스 자료를 학습에서 제외했습니다. 63개 학습·15개 평가이며, 같은 작품의 타 서비스 6문제는 어느 쪽에도 넣지 않았습니다. 원본 checkpoint에서 같은 두 설정을 새로 학습했습니다.

| 조건 | 넷플릭스 분리 정답 /15 | 작품 필드 /9 | 부재 /6 | 오선택 |
| --- | ---: | ---: | ---: | ---: |
| Encoder 고정 + head 학습 | 8 | 6 | 2 | 7 |
| Encoder 전체 + head 학습 | 8 | 6 | 2 | 7 |

전체 수치는 같아도 3개 문제의 선택은 다릅니다. 이 실험에서는 전체 encoder 학습의 일반화 이점을 확인하지 못했습니다. 한 서비스의 5페이지에 대한 진단이며, 학습하지 않은 서비스 전반이나 실제 사이트 개편에 강해졌다는 증거가 아닙니다.

원본 84문제는 모두 이미 결과를 본 개발 자료입니다. 과거 파일명에 `holdout`이 남아 있어도 이번 단계에서는 독립 시험 자료가 아닙니다. 10개 서비스 중 7개에 양성 또는 부재 사례 한쪽만 있어서 자료의 구성도 보강해야 합니다. [자료 감사와 분할 계획](corpus-audit.json).

## Chrome 실행 비용

full encoder 모델의 q8 ONNX는 **14,700,237 B**, tokenizer/config 포함 **14,964,082 B**입니다. JS/WASM 런타임 자산은 이 합계에서 제외합니다. FP32 ONNX와 PyTorch는 실제 18문제 및 17/129/257/384 토큰 동적 입력에서 오차 0.0001 미만이었습니다. q8와 FP32의 logits는 다르지만 native 선택 18개는 같았습니다.

| 실행 | 회고 정답 /18 | 비자명 17필드 최초 추론 중앙값 | Chrome 전체 RSS 시작 → 관측 최대 |
| --- | ---: | ---: | ---: |
| WASM, 1 thread | 11 | 약 1.32초 | 408 → 780 MB |
| WebGPU 요청 | 11 | 약 1.12초 | 412 → 879 MB |

두 브라우저 경로의 실제 logits를 다시 채점했습니다. raw native q8와 브라우저의 최대 logit 차이는 WASM 약0.257, WebGPU 약0.178입니다. 정확도가 같다는 것이 수치적으로 같다는 뜻은 아닙니다. GPU queue 제출 3,470회를 관측했지만 일부 연산은 CPU로 실행되어 순수 GPU 측정이 아닙니다.

다운로드 파일은 작아졌지만 실행 비용은 여전히 큽니다. 표의 RSS는 격리 Chromium 전체 프로세스를 몇 시점에서 관측한 작업 집합이며, 연속 측정한 절대 peak나 모델 단독 물리 RAM이 아닙니다. 시작 대비 관측 최대 증가는 약371 MB/467 MB입니다. 학습을 끝낸 뒤 두 브라우저 실험을 순서대로 실행했으며, 한 대의 개발 장치에서 한 필드의 전체 후보 묶음을 각 1회 측정했습니다. 사전 토큰화 tensor를 사용했으므로 tokenizer·DOM 수집 시간은 제외되고, 로드는 인터넷이 아닌 로컬 서버에서 수행했습니다. 저사양 장치의 보장이 아닙니다.

현재 가중치 용량만 보고 가벼운 기본 기능으로 채택할 수는 없습니다. 다음 실험에서는 더 짧고 구조를 보존하는 입력, 작은 encoder 깊이 또는 증류를 **학습 단계부터** 비교하고, 동일한 의미 정보가 유지되는지 함께 검증해야 합니다.

## 후속 방향과 검증

주된 연구 방향은 소형 학습 모델의 DOM 문맥 표현입니다. 단순 특징 모델은 비용·오류 비교 기준으로 유지합니다. 페이지 범위, 현재 모달, 필드 역할, 보류를 학습 과제로 구분하고, 실제 공통 조상·형제·영역 관계를 관측 단계에서 보존하는 것이 우선입니다. 지금의 후보별 입력에는 전체 tree나 후보 간 직접 비교가 없으므로 템플릿을 길게 만드는 것만으로 해결되지 않습니다.

DOM 특화 큰 모델은 오프라인 비교·교사 후보로 두고, 배포 모델은 별도로 크기와 Chrome 실행 비용을 제한하는 방향을 검토합니다. 이번 학습은 사람이 확인한 정답 ID를 사용한 감독학습이며 증류 실험은 아닙니다. 향후 수집할 실제 모달/검색/로그인/재생/개편 자료를 서비스·작품·시점으로 분리하고, 이전에 본 자료의 정확도와 구분해야 합니다.

[독립 감사](independent-audit.json)는 기존 채점 함수를 사용하지 않고 원시 출력에서 **19개 조건·714개 결정**을 다시 계산했습니다. 이 숫자는 같은 자료의 반복 조건과 훈련 점수를 포함하며 독립 표본 수가 아닙니다. 입력/소스 해시, 후보 ID, 정답 집합, 분모, 모델 내보내기와 브라우저 연결을 검증했습니다. 새 Node 계약 검사 14개, Python 계약 검사 5개, 기존 light-dom 검사 34개가 통과했습니다. 확장 프로그램 전체 E2E는 본체를 수정하지 않아 다시 실행하지 않았습니다.

```powershell
npm run test:dom-adaptation
node eval/dom-adaptation/audit-results.mjs
```
