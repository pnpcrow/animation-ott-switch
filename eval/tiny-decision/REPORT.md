# 초경량 모델 DOM 선택 실측 — 2026-11-13

## 판단 범위

실제 가중치를 로컬에서 실행해 제목·이미지·소개 후보를 선택했다. 이 실험은 **선택한 체크포인트와 입력 구성의 평가**이며, 초경량 모델 전체의 능력이나 앞으로의 사이트 변경 대응력을 판정하는 시험은 아니다. 확장 자동 이동에 모델 판단을 연결하지 않았다.

전체 DOM을 그대로 넣은 것이 아니라 후보 값, 최대 3단계 조상, 짧은 형제 문구, 역할·가시성·메타데이터 출처를 제공했다. 긴 설명과 이미지 URL은 잘랐으며 이미지 픽셀·일부 속성 정보는 주지 않았다. 따라서 정보를 더 보존한 입력이나 DOM 과제로 학습한 모델까지 평가한 결과는 아니다.

## 데이터와 검증 방식

- 실제 공개 16페이지, 8작품, 10 OTT에서 48문제를 만들었다. 38문제는 실제 후보 요소가 3개 이상이다. 정답을 보고 후보를 삽입하지 않았고, 이 자료에서 선호 정답이 후보 상한 밖으로 빠진 사례는 없었다.
- 같은 작품의 페이지·필드를 묶어 조정용 4작품 30문제와 검증용 4작품 18문제로 나눴다. 검증에는 작품 내용이 있는 12문제와 검색/접근 차단 화면의 6문제가 있다. 이미지 후보가 없어 `none`만 있는 1문제는 판단력 증거가 아닌 단순 경로 검사다.
- 10서비스 중 작품 상세의 양성 근거는 7서비스다. WATCHA·쿠팡플레이·Crunchyroll은 이번 익명 캡처에서 검색 셸/차단 화면만 수집됐다. 로그인 후 상세·모달 전체를 확인한 것은 아니다.
- Jev와 Slayer는 공통 5템플릿을 각각 조정용 30문제에서 비교했다. Needle는 실제 WASM 비용 때문에 고정 순서의 필드별 양성/보류 1개씩, 총 6문제에서 도구 형식 4개를 비교했다. 선택 기준은 정답 수, 잘못된 양성 선택 수, 유효 출력 수, 지연 순이다. 검증 결과를 보기 전에 하나를 고정했다.
- 공식 아트워크나 소개의 동등한 변형은 `acceptedIds`로 허용했다. 오류·문맥 초과·잘못된 출력·억제된 호출을 분모에서 빼지 않았다. 정답 요소 선택, 제목 복원 가능성, 실제 OTT 검색·이동 성공은 서로 다른 지표다.

자료의 주석은 에이전트가 공식 페이지를 검토해 작성했으며 독립적인 복수 사람의 주석은 아니다. 기준 휴리스틱은 점수 확인 전에 고정했지만 자료 제작자가 설계했다. 작은 페이지 수, 연관된 필드와 공통 레이아웃 때문에 완전한 블라인드 제품 평가나 일반 정확도 추정으로 볼 수 없다. [데이터 상세](DATASET.md)

## 고정 템플릿으로 실행한 실제 페이지 결과

| 방법                             |         전체 정답 | 실제 작품 필드 / 12 | 올바른 보류 / 6 | 유효 출력 / 18 |    완료 중앙 지연 |
| -------------------------------- | ----------------: | ------------------: | --------------: | -------------: | ----------------: |
| 일반 DOM 규칙, 모델과 같은 입력  | **16/18 (88.9%)** |                  10 |               6 |             18 |             <1 ms |
| LLM-as-Jev 0.6B, `dom-hierarchy` |  **9/18 (50.0%)** |                   3 |               6 |             18 |       6.66초, CPU |

Slayer는 같은 18문제를 실제 브라우저에서도 실행해 동일한 3/18을 얻었다(완료 중앙값 4.91초). Needle는 9번의 구체적인 요소 선택이 모두 오답이고, 올바른 4개는 모두 명시적인 보류다. 공식 엔진의 4개 억제/잘못된 출력은 정답 보류로 바꾸지 않았다. Slayer의 4개 문맥 길이 초과도 실패로 포함했다. Jev의 구체적인 요소 선택 10개 중 3개가 정답이고, 보류한 8개 중 6개가 정답이었다.

표의 지연은 다운로드·모델 로드·DOM 수집을 제외한 완료된 추론의 중앙값이다. 문맥 초과로 즉시 끝난 행은 지연 계산에서 제외했다. Windows 11, Ryzen 7 8840U(8코어/16스레드), Radeon 780M, 약 51.8 GiB RAM에서 실행했다. 모델별 런타임·스레드·정밀도가 다르고 일부 실행이 겹쳤으므로, 이 지연을 최적화된 모델 간 속도 순위로 해석하면 안 된다.

Jev는 CPU float32 4스레드, Slayer는 CPU float32 4스레드 및 별도 Chromium WebGPU/CPU 혼합 경로, Needle는 공식 Cactus 4.1 WASM CPU 1스레드다. **Jev의 브라우저 실행은 검증하지 않았다.**

## 템플릿·구조·입력 형식의 영향

공통 템플릿 조정 결과는 다음과 같다. 독립 검증 정확도가 아니라 템플릿 선택에 사용한 점수다.

| 공통 템플릿           | Jev / 30 | Slayer / 30 |
| --------------------- | -------: | ----------: |
| 최소 지시             |        7 |           4 |
| DOM 계층 관계         |    **8** |           5 |
| 한국어 구조 지시      |        6 |       **6** |
| 제목·이미지·소개 구분 |        7 |           4 |
| 일반 반례 포함        |        6 |           5 |

Needle 조정 결과는 직접 enum 0/6, 구조 설명 enum 0/6, 후보별 도구 1/6, 근거 우선 enum 0/6으로 후보별 도구를 고정했다. 6개 조정 사례는 30개와 같은 선택 안정성을 보장하지 않는다.

| 별도 조건            | 일반 DOM 규칙 |  Jev | Slayer |
| -------------------- | ------------: | ---: | -----: |
| 원본 검증 18개       |         16/18 | 9/18 |   3/18 |
| DOM 구조 문맥 제거   |        미실행 | 7/18 |   5/18 |
| 후보 순서 변경       |         17/18 | 9/18 |   4/18 |
| CSS 클래스 이름 변경 |         16/18 | 9/18 |   4/18 |
| 입력 압축            |         16/18 | 9/18 |   6/18 |
| 가상 상황 12개       |        미실행 | 6/12 |   3/12 |

Jev는 DOM 문맥을 빼면 9/18에서 7/18로 낮아져 구조 정보의 제한적인 도움을 보였다. 하지만 이를 가장 정확한 도구라는 근거로 볼 수 없다. 후보 순서 변경 후에는 18개 중 10개만 같은 선택을 유지했고, 클래스 변경 후에는 16개가 유지됐다. 점수 합계가 같아도 개별 오류는 바뀐다.

Slayer는 순서 변경 전후 모두 유효한 14쌍 중 3쌍만 같은 선택이었다. 클래스 변경의 공통 유효 13쌍은 모두 같은 선택이지만, 그중 10쌍은 같은 오답이다. 입력 압축은 문맥 초과를 4개에서 2개로 줄였지만 잘못된 구체적 선택은 여전히 8개였다. Needle는 실행 비용과 엔진 계측 한계 때문에 이 추가 변형 시험을 수행하지 않았다.

가상 상황은 현재 모달과 숨겨진 이전 화면, 오래된 Watch/서비스 메타데이터, 회차와 작품 제목, 미리보기 영상 교체, 추천 작품의 소개, 시즌/매체가 다른 검색 후보, 관측된 번역 제목, 근거 부족 보류 등을 포함한다. 실제 OTT 검색 성공 사례로 합산하지 않았다. [별도 상황과 압축 규칙](CHALLENGE.md)

변형 결과는 원본과 같은 사례를 재사용했다. 후보 순서/CSS 변경은 미래의 실제 사이트 개편을 재현한 것이 아니다. 같은 오답을 계속 고르는 경우를 포함하므로 선택 유지율만으로 안정적인 정확도를 주장하지 않는다.

Slayer의 0부터 시작하는 번호와 저자 스타일 JSON을 사용한 사후 형식 제어도 각각 3/18이었다. 원본 1-based 재실행은 유효한 14개 선택이 모두 같았다. 이 제어는 새 검증 자료나 재선정 근거로 사용하지 않았다. [형식 제어 원자료](results/slayer-format-controls.json)

Jev 저자 형식 제어는 저자의 Jinja 출력과 18개 user 문자열을 byte 단위로 맞추고 114개 suffix 토큰 경계를 대조했다. 결과는 동일한 9/18이었지만, 실제 작품 필드는 5/12, 올바른 보류는 4/6으로 오류 구성이 달라졌다. 공통 5개 템플릿과 별도로 고정한 형식 제어이며, 그 결과로 우승 템플릿을 다시 고르지 않았다. [저자 형식 결과](reports/jev-author-format.json)

## 제목 요소와 복원 가능한 제목은 구분해야 한다

| 고정 템플릿, 작품이 실제 있는 제목 4개 | 정답 제목 요소 | 기존 정규화 후 제목 복원 | 작품이 없는 제목 2개의 올바른 보류 |
| -------------------------------------- | -------------: | -----------------------: | ---------------------------------: |
| Jev                                    |            2/4 |                  **4/4** |                                2/2 |
| Needle                                 |            0/4 |                      0/4 |                                1/2 |
| Slayer                                 |            1/4 |                      2/4 |                                1/2 |

Jev는 서비스 문구가 붙은 문서 `<title>`을 골라 엄격한 요소 선택에서는 틀린 2개도 기존 정규화 후 작품명을 복원했다. 이는 제목 용도에서 검토할 가치가 있는 결과다. 다만 4개 작품의 보조 측정이며, 실제 작품 이미지·소개 8개에서는 1개만 정답 요소를 골랐다. 제목 결과를 이미지·소개 품질까지 확대해서 해석하면 안 된다. 관측 원문과 모델에 보여 준 제한된 제목 값으로 각각 계산한 복원 개수는 이 사례들에서 같았다.

제목 복원은 이미 있는 서비스별 `cleanPageTitle`과 `normalizeTitle`을 사용한다. 정답 제목이나 별칭을 정규화 힌트로 주지 않았다. 모델이 고른 관측 후보만 처리한 뒤 정답과 비교했다. 따라서 이는 **모델과 기존 규칙의 조합**이며, 순수 모델 정확도나 작품의 시즌·판본·제공 여부·이동 성공 증거가 아니다. 작품이 열려 있지 않은 사례에 제목 복원 점수를 주지 않는다. [지표 설명](TITLE_RECOVERY.md)

## 실행 가능성과 비용

| 모델                       |         이번 가중치 | 확인한 실행 경로                                     |
| -------------------------- | ------------------: | ---------------------------------------------------- |
| 저자 LLM-as-Jev Qwen3 0.6B | 1,192,135,096 bytes | PyTorch CPU; 브라우저 이식은 미검증                  |
| Needle 3, 배포된 121M 파일 |    35,335,380 bytes | 공식 Cactus 4.1, Chromium WASM CPU                   |
| Slayer 149M                |   597,366,956 bytes | PyTorch CPU 및 자체 ONNX 변환 후 Chromium WebGPU/CPU |

Slayer의 ONNX 파일은 654,464,302 bytes다. tied embedding을 입력과 출력에 따로 저장해 원래 가중치보다 크다. 실제 유효한 브라우저 선택 14개가 CPU와 모두 같았고 4개 문맥 초과도 동일했다. GPU queue 제출 12,420회를 관측했으나 일부 연산은 CPU였다. 반복 prefix 계산을 하는 검증용 그래프여서 최적화된 배포 구현은 아니다. [Slayer 상세](slayer/README.md)

Jev/Slayer는 숫자 한 토큰이나 자유 생성 텍스트가 아니라 **전체 숫자와 닫는 괄호 suffix의 로그 확률 합**을 비교했다. KV 공유 구현과 전체 재계산의 최대 오차는 각각 약 `5.23e-6`, `2.87e-6`이었다. Slayer GPU/CPU의 최대 차이는 `6.14e-5`였다. 모델 파일 체크섬, 실제 파라미터 수, 선언된 가중치 tying도 검사했다.

Needle 결과는 모델뿐 아니라 공식 엔진의 문법 제약·인자 검증/보정·신뢰도 차단을 포함한다. 차단 전 제안도 진단으로 보존했으며 차단을 정답 `none`으로 처리하지 않았다. 별도 날씨 도구 양성 대조는 정상 동작했다. 공식 엔진의 신뢰도와 Jev/Slayer의 선택지 softmax 모두 이 DOM 과제의 정답 확률로 보정된 값이 아니다. [Needle 상세](needle3/README.md)

Needle 공식 응답은 입력 토큰 수·문맥 사용량·내부 절단 여부를 제공하지 않는다. 특히 후보별 도구 방식은 질문을 도구마다 반복한다. 모든 입력이 절단 없이 처리됐는지 확인할 수 없으므로 이 결과를 순수 모델 이해 능력으로 해석할 수 없다. 메모리 수치도 음수가 관측돼 RAM 실측값으로 사용하지 않았다.

## 프로젝트에 적용할 판단

현재 구성에서 모델이 일반 DOM 규칙보다 빠르고 정확하다는 근거는 얻지 못했다. 기본 추출을 대체하거나 모델의 신뢰도만으로 자동 스위치를 허용할 단계는 아니다. 특히 대표 이미지와 소개 선택, 접근 차단/검색 화면의 구분을 따로 검증해야 한다.

DOM을 공통 형식으로 수집하고 후보를 한정하는 접근은 계속 활용할 수 있다. 모델은 관측 후보 ID만 선택하게 하고, 작품명 정규화와 상세 페이지 재검증은 독립적으로 유지하는 편이 맞다. 다음 모델 실험은 추가 학습 없는 일반 의사결정 모델에 지시문만 더 붙이는 것보다, 이미지 alt·크기·근접 제목·모달 상태를 보존한 입력과 한국어 DOM 선택 학습 자료를 우선 준비할 필요가 있다. 자료는 작품뿐 아니라 사이트·레이아웃·시간 변화도 분리해 검증해야 한다.

이번에는 모델을 추가 학습하지 않았다. 선택형 AI 후보를 완전히 배제하는 결론이 아니라, **현재 체크포인트·직렬화·런타임 조합을 자동 선택 기능으로 채택하지 않는 판단**이다. 제목 정규화 후 복원 가능성은 다음 실험에서 별도로 살펴볼 가치가 있다.

모델 도구·다운로드·Python/ONNX 의존성은 실험 디렉터리와 명시적 실행 명령에만 있다. 기본 확장에 AI 의존성을 추가하지 않았다. 모델이 선택한 ID는 관측 후보에 속하는지 검증하고, 평가 중 함수나 이동 동작은 실행하지 않았다.
