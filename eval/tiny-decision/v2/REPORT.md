# DOM 템플릿 고도화 평가 결과

2026-11-13에 같은 고정 모델 가중치로 다시 평가했습니다. **템플릿과 DOM 표현을 개선하면 결과가 달라졌지만, 이번 설계만으로 안정적인 자동 선택을 확보하지는 못했습니다.** Jev는 실제 작품 필드 선택이 개선된 대신 비작품 화면 오인이 늘었습니다. Slayer는 입력 예산 초과를 줄였으나 잘못된 선택이 많았고, Needle의 선택된 v2 설계는 공식 엔진을 통과한 정답이 없었습니다.

이 보고서는 선택된 요소의 정확도입니다. 검색 결과의 동일 작품 판정, OTT 제공 여부, 실제 페이지 이동 성공률을 측정한 결과가 아닙니다. 모델을 확장 프로그램에 기본 탑재하지 않고 별도 평가 도구로 유지합니다.

## 무엇을 바꾸었는가

- CSS·URL 중심 입력에 관측된 alt·크기·부모 역할·주변 제목·앞뒤 텍스트·숨김·다이얼로그 정보를 보강했습니다. 관측할 수 없는 값과 모호하게 다시 찾은 노드는 추측으로 채우지 않았습니다.
- 제목/회차/서비스 문구, 표지/로고/회차 썸네일, 줄거리/홍보/회차 소개를 구분하는 기준과 가상 대비 예시를 만들었습니다. 검색 카드와 열린 작품 화면의 차이도 예시로 설명했습니다.
- Jev는 8가지, Slayer는 6가지 다중선택 설계를 탐색했습니다. Needle는 중립 후보 ID, 필드별 enum, 후보별 도구, 관계 표현 등 4가지 도구 스키마를 비교했습니다.
- Slayer는 각 후보를 적합/부적합으로 판단한 뒤 답 순서를 뒤집어 다시 묻는 방법도 별도로 시험했습니다. 후보마다 두 번 실행하는 전체 비용을 기록했습니다.
- 정답·평가용 작품/후보 ID의 프롬프트 유입, 미등록 도구 이름, 후보 누락, 결과 누락, 잠금 이후 자료 변경을 검사하는 계약을 추가했습니다.

같은 feature pack을 사용해도 템플릿마다 일부 속성의 생략 여부와 토큰 예산에 따른 축약 tier가 달라집니다. 아래 차이는 **관측·직렬화·지침·예시의 합성 효과**이며, 문구 하나만 바꾼 순수 비교가 아닙니다. [설계·재현 절차](README.md)에 각 조건을 기록했습니다.

## 개발 자료와 신규 검증의 분리

이미 평가한 기존 48문제는 전부 개발용으로 재분류했습니다. 12개 층화 선별 자료를 사용하고, Jev/Slayer의 상위 2개를 48개 전체에서 비교했습니다. Jev는 `scope-contrast` 26/48, Slayer는 `json-evidence` 13/48, Needle는 `field-enum` 2/12로 선택이 고정됐습니다. 이 개발 점수는 신규 정확도로 보고하지 않습니다.

모든 선택은 **2026-11-13 12:36:11 UTC**에 [전체 잠금](global-freeze.json)으로 기록한 뒤 신규 후보 입력·정답·예측을 열었습니다. 새로운 자료는 **4작품의 작품 페이지 4개와 검색·도움말 페이지 2개, 총 6페이지에서 나온 18개 필드 문제**입니다. 작품 필드가 있는 12개와 없는 6개를 분리해 채점합니다. 같은 페이지의 세 필드는 서로 독립된 웹페이지가 아니며, 작은 표본에 대한 통계적 일반화는 하지 않습니다.

정답은 평가 모델의 출력을 보기 전에 별도 에이전트가 공개 페이지 캡처·HTML·주변 요소로 검수했습니다. 같은 개발 세션 안의 실용적 분리이지 외부 기관의 독립 벤치마크는 아닙니다. 후보 수집 후 정답을 끼워 넣지 않았고 신규 양성 정답의 후보 포함률은 12/12였습니다. [자료 출처·주석·접근 제한](DATASET.md)을 함께 참고해야 합니다.

## 같은 신규 자료에서의 비교

| 모델 / 조건 | 전체 정답 / 18 | 실제 필드 선택 / 12 | 필드 없음 정답 / 6 | 잘못된 실제 후보 선택 | 예산 실패 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Jev 기존 v1 | 8 | 3 | 5 | 7 | 0 |
| Jev `legacy-enriched` | 4 | 4 | 0 | 13 | 0 |
| Jev 선택된 v2 | 8 | 7 | 1 | 9 | 0 |
| Slayer 기존 v1 | 4 | 1 | 3 | 7 | 5 |
| Slayer `legacy-enriched` | 4 | 1 | 3 | 13 | 0 |
| Slayer 선택된 v2 | 6 | 2 | 4 | 11 | 0 |
| Needle 선택된 v2 | 0 | 0 | 0 | 0 | 0 |
| 기존 일반 DOM 규칙 | 15 | 11 | 4 | 3 | 0 |

오류와 억제된 출력은 정답에서 제외하고 **18개 전체 분모에는 포함**합니다. 모든 문제에 `none`만 답하는 기준은 6/18이며 실제 필드 선택은 0/12입니다. Needle의 잘못된 실제 후보 선택이 0이라고 정확한 것은 아닙니다. 17개는 엔진에서 억제됐고 유효 출력 1개도 작품 필드를 `absent`로 잘못 판단했습니다.

일반 DOM 규칙은 v1에서 고정한 서비스·작품명과 무관한 규칙을 변경 없이 적용했습니다. 이 기준은 기존 compact document/options를 읽으므로 v2 모델과 완전히 동일한 직렬화 입력을 받지는 않습니다. 신규 자료에 맞춘 규칙 튜닝은 하지 않았습니다. 여기서도 3개 오선택이 있어 확장 프로그램 전체의 성공률이나 자동 이동 허용 근거로 쓰지 않습니다.

Jev는 실제 작품의 소개 4/4와 이미지 2/4, 제목 1/4를 맞혔습니다. 기존 v1 대비 실제 필드 선택은 3→7개로 늘었으나 비작품 화면의 올바른 보류는 5→1개로 감소해 전체 8/18은 같았습니다. 같은 보강 입력 계열의 `legacy-enriched` 4/18보다 선택된 새 설계가 낫지만, 새 설계도 잘못된 실제 후보 선택이 9개입니다. 개발 자료에서 추가한 상세 필드 예시(`field-worked`)가 전체 개발 점수에서 더 낫지는 않았습니다(25/48 대 26/48).

Slayer의 전체 점수는 4→6개로 늘었지만, 두 방식 모두 실행된 13문제에서는 각각 4개 정답이었습니다. 개선된 2개는 v1의 입력 예산 초과 문제 5개 중 복구한 문제입니다. 따라서 이를 순수한 의미 이해 향상으로 해석하지 않습니다. v2 두 조건은 모두 18문제를 실행했고 새 설계가 `legacy-enriched`보다 2개 더 맞혔습니다. 자세한 대응 비교는 [Slayer 결과](slayer/RESULTS.md)에 있습니다.

`legacy-enriched` 비교에도 제한이 있습니다. Jev는 v2부터 저자 형식처럼 사용자 턴 말미 개행을 정리합니다. Slayer는 기존 한국어·1-based에서 영문·0-based로 바뀝니다. 기존 v1 대조군 자체는 이전 프롬프트·runner를 그대로 사용했습니다.

## 제목 정제 후의 복원은 별도 지표

요소를 잘못 골라도 서비스 장식이 붙은 같은 제목이면 기존 확장 프로그램의 제목 정제 함수로 복원할 수 있습니다. 모델 결과를 보고 정제 규칙을 바꾸지 않고, production `cleanPageTitle`에 정답 참조 없이 `references=[]`로 적용했습니다. 정답 문자열은 정제 후 동등성 채점에만 사용했습니다. 원래 요소 정답률은 변경하지 않습니다.

| 신규 실제 작품의 제목 4개 | 정확한 요소 선택 | 기존 정제 후 제목 복원 |
| --- | ---: | ---: |
| Jev 기존 v1 | 1/4 | 3/4 |
| Jev `legacy-enriched` | 1/4 | 2/4 |
| Jev 선택된 v2 | 1/4 | 2/4 |
| 기존 일반 DOM 규칙 | 4/4 | 4/4 |

이번 표본에서는 원본 후보 전체 문자열과 모델에 보인 축약 문자열의 복원 점수가 같았습니다. v2는 실제 기록된 96자 tier를 재구성했으며 더 긴 v1 option 문자열로 대신 평가하지 않았습니다. 시즌 선택 heading이나 회차 제목을 잘못 고른 경우는 일반 정제로 복원되지 않았습니다. 검색·도움말 제목에는 복원 성공을 정의하지 않습니다. 선택된 v2의 이미지·소개 개선을 제목 검색 품질까지 개선된 것으로 확대 해석하면 안 됩니다. [보조 평가 원시 기록](reports/title-recovery.json)에 정제 전후와 실패를 남겼습니다.

## 선택 편향과 엔진 억제

Slayer의 이진 후보 판정은 개발 12문제에서 154회 추론을 실행했습니다. 답 순서를 반대로 하면 77/77 후보의 이진 선택이 뒤집혔고, 양쪽 log-odds 평균과 개발용 단일 threshold를 사용해도 최선은 모두 `none`으로 답하는 6/12였습니다. 실제 필드 정답 0/6으로 사전 진행 조건을 충족하지 못해 신규 자료에서는 실행하지 않았습니다. 문제당 후보 전체 추론 합산 중앙값은 13.86초, 총 210.96초였습니다. 선택지 softmax나 log-odds를 정답 확률로 보정한 값처럼 사용하지 않습니다.

Slayer의 고정 템플릿에서 개발 6문제의 후보 순서를 뒤집었을 때 같은 후보 ID를 유지한 경우는 0/6이었고 정답은 2/6→0/6이었습니다. 순서 진단은 새 독립 표본 수에 더하지 않습니다.

Jev도 신규 18문제의 후보를 역순으로 배치하면 동일 후보 ID를 유지한 경우가 **5/18**에 불과했고 정답은 8/18→7/18로 바뀌었습니다. 원래 정답 중 4개가 틀리고 원래 오답 중 3개가 맞아, 정답 개수만 보면 잘 드러나지 않는 불안정성이 있습니다. 두 개의 동등한 정답 후보 사이에서 바뀐 선택도 ID 유지율에서는 변화로 세며, 정답 여부는 허용 정답 목록으로 별도 채점합니다.

Needle의 신규 18문제 내부 단일 제안은 모두 `absent`였습니다. 이 제안만 채점하면 없는 필드 6개와 우연히 일치하지만 실제 필드 12개는 하나도 찾지 못했습니다. 억제된 제안을 최종 정답으로 승격하지 않았습니다. 프롬프트·관측 표현을 바꿔도 이번 네 설계에서는 유용한 양성 선택을 얻지 못했다는 뜻이며, 모든 가능한 Needle 템플릿이 실패한다는 증거는 아닙니다. [Needle 원시 결과와 해석](needle/README.md)에 공식 엔진과 내부 제안을 분리했습니다.

Needle의 기존 방식은 실행 비용을 고려해 사전에 정한 **동일 6문제**에서 대조했습니다. 각 필드의 첫 양성/없음 사례를 선택했으며 실제로는 작품 페이지 1개와 검색 페이지 1개의 세 필드씩입니다. 아래 6개 점수를 위의 전체 18개 점수와 직접 비교하지 않습니다.

| Needle 동일 6문제 | 전체 정답 | 실제 필드 선택 | 없음 정답 | 잘못된 실제 후보 선택 |
| --- | ---: | ---: | ---: | ---: |
| 기존 `tool-routing` | 4/6 | 2/3 | 2/3 | 2 |
| 새 `field-enum` | 0/6 | 0/3 | 0/3 | 0 |

새로 고도화한 설계가 이 대조에서는 오히려 나빠졌습니다. 기존 방식도 실제 후보 선택 4개 중 2개가 오답이므로 안전한 자동 선택 근거로 쓰기 어렵습니다. 모델 경계에 전달한 두 문자열의 최대 합계는 6,631→1,348자로 줄었고 관측 중앙값은 19.91→12.48초였지만, 실행 시점의 CPU 경합도 달라 이를 템플릿만의 속도 향상으로 단정하지 않습니다. 입력을 더 짧고 구조적으로 만드는 것이 정확도 향상을 보장하지는 않았습니다.

## 실행 환경과 적용 판단

Jev는 고정된 저자 Qwen3 0.6B 배포본을 PyTorch CPU float32로, Slayer는 고정 149M 배포본을 PyTorch CPU로 실행했습니다. Needle는 고정 공식 모델과 Cactus 4.1 WASM CPU를 사용했습니다. 이번 작업은 WebGPU 속도를 새로 검증한 실험이 아닙니다. 실행 중 CPU와 메모리를 공유했으므로 관측 지연시간을 독립 성능 벤치마크나 속도 개선율로 해석하지 않습니다.

템플릿 개선은 계속할 가치가 있지만, 요소 후보를 고르는 능력과 작품 화면 여부를 판별하는 능력을 별도로 관리해야 합니다. 현재 결과로 모델의 선택만 믿고 자동 이동을 허용하기는 어렵습니다. 다음 검증에서는 작품 화면 범위 판정과 필드 추출을 분리하고, 판정이 엇갈릴 때 보류하는 구성을 새로운 자료로 평가하는 것이 적절합니다. 이번 신규 18문제도 결과를 확인했으므로 이후 템플릿 조정에 사용한다면 개발 자료로 재분류해야 합니다.

원시 실행·해시·선택 기록은 [Jev 보고서 디렉터리](reports/), [Slayer](slayer/), [Needle](needle/reports/)에 있습니다. 재현 명령과 데이터 제약은 [README](README.md)를 참고하세요.

## 저장소 검증

기존 계약 테스트 22개와 v2 계약 테스트 49개가 로컬에서 통과했습니다. 데이터·템플릿·선택 잠금 해시, 계획된 문제 전체 포함 여부, 정답 비노출과 실제 모델 결과를 검사했습니다. 실험 코드·자료·기록만 변경했으므로 확장 프로그램의 전체 브라우저 E2E를 다시 실행하지 않았습니다. GitHub Actions는 [기반 커밋의 실행](https://github.com/pnpcrow/animation-ott-switch/actions/runs/43426410584)에서 계정 Actions 예산 제한으로 작업이 시작되지 않았습니다.
