모두 HTTPS이며 `www`/비-`www` 이동, 서비스별 검색·상세·재생 경로와 같은 주소에서 열리는 모달을 처리하기 위해 `/*` 경로를 사용합니다. `tabs` 권한을 요구하지 않아도 탭 생성·이동은 가능하며, 호스트 권한은 해당 사이트의 URL/콘텐츠 접근과 연결됩니다. 임의 도메인 전체 권한은 없습니다. 이미지 URL의 일반 `<img>` 요청은 위 호스트 조회와 별개입니다.

## storage 권한 제거 근거

0.1.6에는 `storage` 권한과 `chrome.storage.local.setAccessLevel({ accessLevel: "TRUSTED_CONTEXTS" })` 호출이 있었으나 `chrome.storage`에 실제 데이터를 읽거나 쓰지 않았습니다. 0.1.7에서 둘 다 제거했습니다. IndexedDB는 표준 웹 저장소 API이므로 이 권한을 제거해도 보관함 저장 이름·스키마·기록은 바뀌지 않습니다.

## 스토어 데이터 항목 해석

웹 콘텐츠와 지원 OTT URL의 읽기·저장은 공식 양식의 웹사이트 콘텐츠·웹 기록에 직접 대응합니다. 로컬 UUID는 설치별 수정 기록의 출처이며, 재생/임시 탭 상태는 동작 중 일시적으로만 처리합니다. 개인 식별 정보·사용자 활동 체크 권고는 이 두 사실을 공개하기 위한 보수적 매핑이며 사용자 신원 수집·행동 분석을 한다는 뜻은 아닙니다. [공식 데이터 처리 FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)와 [개인정보 입력란 안내](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)를 기준으로 판단했습니다.

## 검토 시 유지할 사실

- 개발자 서버·분석 SDK·자동 백업 업로드는 없습니다. “인터넷 전송 없음”은 사실이 아니므로 쓰지 않습니다.
- `credentials: omit` 설명은 공개 HTTP 조회에 한정합니다. 실제 웹 탭과 이미지 요청까지 인증정보가 없다고 단정하지 않습니다.
- 기본 지역 코드와 사용자가 선택하는 구독 서비스는 실제 위치·결제내역 수집과 다릅니다.
- 로컬 데이터와 JSON 백업은 별도 앱 암호화가 없습니다. 브라우저 저장소라는 이유만으로 암호화되었다고 설명하지 않습니다.
- Google Drive·WebLLM 개발 실험과 설치용 확장의 동작을 구분합니다.
- 영구 삭제와 tombstone 삭제, 검색 결과 초기화와 브라우저 전체 캐시 삭제를 구분합니다.
- 저장소 공개가 사용자 개인 보관함을 공개하는 것은 아닙니다. 공개하는 소스·테스트 자료에 실제 세션·개인 데이터가 없는지는 별도로 확인해야 합니다.
