# 8개 작품 교차 검증 · 2026-11-13

제공받은 8개 작품을 10개 서비스에서 조사하고, 공식 카탈로그 근거와 확장이 실제 반환한 결과를 분리해 기록했습니다. **현재 자료로 모든 OTT 간 자동 이동이 성공한다고 말할 수 없습니다.** 로그인·접근 제한, 검색 범위, 판본·별칭 차이와 추출 오류를 구분하는 것이 이번 검증의 목적입니다.

## 자료와 검사 범위

- [기준 작품](../qa/cross-check/cases.json): 사용자 입력, 검사 검색어, 출발 작품 주소, 판본 주의사항.
- [80개 조합의 공식 근거와 수정 전 결과](../qa/cross-check/official-evidence-2026-11-13.json): 작품 8개 × 서비스 10개. 공식 API·공개 검색·상세 페이지·검색 색인을 관측 방식별로 구분합니다.
- [실제 관측 기반 WebLLM 평가 자료](../qa/cross-check/webllm-eight-works.json): 조정용 4작품과 검증용 4작품, 독립적으로 정한 정답과 출처.

기준 버전은 `0.1.3`, 커밋은 `45f0077a8c14b41dd09625d83dfb1d6b8ad1cabf`입니다. HTTP 검사는 2026-11-13 09:13:09–09:13:39 UTC, 확장 검사는 09:13:27–09:21:17 UTC에 실행했습니다. 한국 호스트의 독립 Chromium 프로필과 익명 공개 페이지를 사용했으며 사용자의 쿠키·계정은 복사하지 않았습니다. 웹 검색 도구의 요청 지역은 별도로 확정하지 않았습니다.

HTTP 검사는 80개 검색을 실행했습니다. 확장 검사는 작품별 지정 출발 페이지를 읽은 뒤 **다른 9개 서비스에 72회 `openResolved`를 호출**했습니다. 출발 서비스 자체의 8개 칸은 `source-only`이며 이동 성공으로 세지 않습니다. 모든 서비스 쌍의 양방향 이동을 전수 검사한 것은 아닙니다. `직접 검색 URL`도 기록하지만 URL 생성만으로 해당 서비스 검색이나 이동 성공을 인정하지 않습니다.

`어느 마녀가 죽을떄까지`의 `떄`는 기준 자료에서 `때`로 교정했습니다. 이는 제품의 임의 오타 교정 기능을 검사한 결과가 아닙니다. HTTP 검사는 제공된 짧은 검색어를 사용하고, 확장 검사는 실제 출발 페이지에서 추출한 제목을 사용합니다. 따라서 니아의 전체 부제, Re:제로의 감독판처럼 검색 입력이 달라지는 경우 두 결과를 단순한 성능 향상으로 비교하면 안 됩니다.

## 발견한 기본 기능 문제

- Apple 웹 검색의 `결과 없음`은 전체 카탈로그에 대한 부재 증거가 아니었습니다. 동일 시점의 한국 작품 상세가 HTTP 200으로 열리는 반례를 확보해 `unknown`으로 남기도록 수정했습니다.
- 애니플러스 검색 카드는 주소 없이 내부 버튼 동작으로 이동했습니다. 상세 페이지에는 숨겨진 검색 제목도 있어 현재 작품의 제목과 구분해야 했습니다.
- 웨이브 자막·더빙 중복과 티빙 포스터용 제목 장식은 실제 제목 판정과 후보 선택에서 추가 검증이 필요했습니다.
- Apple 카드캡터의 초기 `imageUrl`은 이미지가 아니라 HTML 작품 주소였습니다. 라프텔 약사의 초기 소개는 `{줄거리}`였습니다. 이 값을 정상 정답으로 삼지 않았으며 WebLLM 평가 자료에서도 제외했습니다.
- Crunchyroll의 검색 색인에는 작품이 있어도 직접 요청은 일반 홍보·브라우저 안내 화면을 반환했습니다. `Crunchyroll: Watch Popular Anime, Play Games & Shop Online`을 작품명으로 사용하는 것은 잘못된 추출입니다.

### 수정 후 재검증

수정 후 애니플러스·Apple·웨이브·티빙 32개 칸을 재검사하고, 티빙 상세 추출 보완 후 8개 칸, 애니플러스 더빙 중복 보완 후 프리렌 1개 칸을 다시 확인했습니다. [실행 근거](../qa/cross-check/runtime-evidence-2026-11-13.json)에 완료 시각·빌드 SHA-256·실제 응답을 남겼습니다. 이 파일의 최종 80칸은 각 칸의 가장 최근 관측을 합친 것이며, 수정하지 않은 서비스에는 수정 전 관측이 남아 있습니다. 동일한 최종 빌드로 80칸을 다시 실행했다고 해석하면 안 됩니다.

최종 합성 표는 출발 확인 8, 자동 이동 6, 후보 복수 1, 확인 불가 58, 해당 검색어의 부정 결과 7입니다. 72개 대상 서비스 중 6개 자동 이동은 라프텔 → 웨이브(어느 마녀·Re:제로 감독판), 라프텔 → 애니플러스(니아·Re:제로 감독판), 라프텔 → 티빙(어느 마녀·Re:제로 감독판)입니다. 초기 수정본에서는 애니플러스 프리렌 원본을 열었지만, `한국어더빙` 중복 표기도 같은 작품으로 비교한 최종 구현은 임의 선택을 보류합니다. 이를 성공률을 높이려고 첫 후보 선택으로 되돌리지 않았습니다.

추가 역방향 5회는 자동 이동 4회와 프리렌 후보 복수 1회였습니다. 프리렌의 라프텔 자막·더빙 2개와 티빙 자막·더빙 2개는 각각 `candidateUrl`을 명시해 재검증한 뒤 이동했습니다(총 4회). 직접 검색 URL 생성만으로 이동 성공을 주장하지 않습니다. 없는 이미지가 현재 HTML 주소가 되는 오류와 `{줄거리}` 소개는 회귀 검사로 방지합니다. 이미지·소개를 사이트가 제공하지 않으면 빈 값으로 남길 수 있습니다.

최종 0.1.4 타입 검사·빌드, 단위 검사 339개, 실제 MV3 확장을 로드한 브라우저 회귀 검사 28개가 통과했습니다. 회귀 검사에는 애니플러스 카드 클릭/상세 불일치/중복, 티빙 회차 장식/시즌 충돌과 기존 검색·캐시·모달 동작이 포함됩니다.

## 재현 방법

저장소 루트에서 실행합니다. HTTP 모드는 현재 소스의 검색 함수를 사용하며, 확장 모드는 먼저 빌드한 `dist`를 독립 임시 프로필로 복사합니다. 실제 공개 사이트에 요청하므로 계정 상태·시점·사이트 변경에 따라 결과가 달라집니다.

```powershell
npm ci
npm run build
node scripts/cross-check.mjs --mode=http --output=artifacts/cross-check-http.json
node scripts/cross-check.mjs --mode=extension --output=artifacts/cross-check-extension.json
node scripts/cross-check.mjs --mode=extension --providers=aniplus,apple,wavve,tving --output=artifacts/cross-check-extension-focused.json
node scripts/cross-check.mjs --mode=extension --works=witch,frieren --providers=wavve,tving --output=artifacts/cross-check-two-works.json
node scripts/cross-check.mjs --mode=extension --cases=qa/cross-check/reverse-cases.json --verify-candidates=true --output=artifacts/cross-check-reverse.json
```

수동 확인에서는 설정 또는 사이드바의 **검색 결과 초기화** 후 출발 작품을 엽니다. 검색어, 후보의 자막/더빙·시즌·판본, 선택한 상세 주소와 실제 상세 제목을 비교합니다. 후보가 여러 개인 경우 선택 경로를 별도로 실행하고, 카드 제목과 상세 제목이 다르면 최종 이동하지 않는지 확인합니다. 로그인·접근 확인이 나오면 그 상태를 기록하며 작품 없음으로 바꾸지 않습니다. 본편 재생 검사는 실제 한국 구독 계정에서 별도로 진행해야 합니다.

## WebLLM 평가

확장 기본 기능과 분리된 [선택형 평가 도구](../eval/webllm/README.md)를 사용합니다. 실제 자료는 마녀·프리렌·약사·니아 4작품을 조정용, 사쿠라·Re:제로·던전밥·저녁식사 4작품을 검증용으로 나눴습니다. 모든 정답은 모델 실행 전에 공식 관측을 보고 정했습니다. 정답·출처·분할명은 모델 입력에 전달하지 않습니다.

평가의 핵심은 이미 알고 있는 제목을 외워 맞히는 것이 아니라 관측된 제목·이미지·소개 ID와 작품 후보를 선택하는 것입니다. 감독판/영화/총집편 충돌, 자막·더빙 중복, 근거 없는 부제 축약, 검색 차단 시 보류를 포함합니다. 실제 후보 주소만 사용하며 모델이 URL을 생성하지 않습니다. 선택 모델 다운로드는 명시적으로 실행할 때만 발생하고 기본 확장 빌드에는 포함되지 않습니다.

```powershell
npm --prefix eval/webllm ci --ignore-scripts
node scripts/eval-webllm.mjs
# 다른 터미널에서 실행: 모델을 실제로 내려받고 GPU 추론합니다.
node scripts/eval-webllm-smoke.mjs --download-model --evaluate --dataset=qa/cross-check/webllm-eight-works.json --output=artifacts/webllm-eight-works-evaluation.json
```

AMD Radeon 780M에서 Qwen3 0.6B, Qwen2.5 1.5B·3B를 실제 실행했습니다. 각 모델에서 고정된 v1/v2/v3 템플릿의 조정용 점수를 비교한 뒤 하나를 고정하고 검증용 4개를 한 번 실행했습니다. 전체 답 일치는 각각 2/4, 1/4, 1/4였으며 세 모델 모두 조정용 최소 선별 기준을 통과하지 못했습니다. **모델은 기본 확장이나 자동 이동에 연결하지 않았습니다.** 실제 응답·처리 시간·자료/템플릿 해시와 판정 의미는 [WebLLM 실행 기록](../eval/webllm/RESULTS.md)에 있습니다.

이 8개 자료의 제목·이미지·소개 후보는 종류마다 최대 하나이므로 해당 필드 점수가 실제 DOM 추출 정확도를 증명하지 않습니다. 독립된 작품 후보 일치·판본·불완전 검색 판단에는 여전히 오류가 있었습니다. 일반 DOM 후보 수집 도구와 별도의 경쟁 메타데이터 회귀 자료를 제공했으며, 원본 화면 구조 변경을 평가하려면 더 다양한 실제 후보 자료가 필요합니다. 이 제한을 숨기거나 정답을 프롬프트에 넣어 점수를 맞추지 않았습니다.
